# CLAUDE.md

Seite des Kinderspiels Mitwachsen (www.mitwachsen-spiele.de) von Lars Michaelis, im Voxel-Stil. Astro 7, statische Ausgabe, Sprache Deutsch. Das Spiel stammt aus dem Repo von larmic.de.

## Befehle

```bash
npm run dev      # Entwicklungsserver auf http://localhost:4321
npm run check    # Guard-Gate: Typen und Inhalts-Schemas prüfen – muss grün sein
npm test         # Guard-Gate: Unit-Tests (Vitest) mit Mindest-Abdeckung der reinen Module, Eigenschafts-Tests über Stichprobe und Regressions-Seeds (vitest.config.ts) – muss grün sein
npm run test:deep # Guard-Gate: Unit-Tests ohne Abdeckung über die vollen Seed-Bereiche (MITWACHSEN_DEEP=1); im Job static der Pipeline und in gates:ci, nicht im Pre-Commit-Hook
npm run lint     # Guard-Gate: ESLint – muss grün sein
npm run format   # Prettier; `npm run format:check` ist das Guard-Gate
npm run arch     # Guard-Gate: Architekturregeln (dependency-cruiser) – muss grün sein
npm run build    # statische Seite nach dist/
npm run verify   # Guard-Gate nach dem Build: gültiges HTML, keine toten internen Links und Sprungmarken, Bundle-Gate (Startseite ohne Spiel, JS-Budget), Seiten-Gate (keine externen Ressourcen), App-Gate (Manifest, Icons, Service Worker speichert alles fürs Spiel samt Three.js und allen Welt-Paketen, vorab Gespeichertes ohne Three.js im Budget `PRECACHE_BUDGET` in `scripts/verify-pwa.ts`)
npm run test:e2e # Guard-Gate nach dem Build: Smoke-Test im Browser (Playwright, e2e/, Projekte in playwright.config.ts: `site` Seiten ohne Spiel in e2e/site.spec.ts, `game` Spiel in 2D ohne WebGL mit Test-Uhr, `3d` nur Tests mit Tag @3d mit WebGL, einzeln, `pwa-update` einzeln): Seiten, Spiel, 404, ohne Konsolenfehler; App: Manifest, installierbar laut Chromium (CDP im vollen Chromium, mit Gegenprobe, e2e/installable.spec.ts), Service Worker, Spiel ohne Netz (e2e/pwa.spec.ts), Updates mit zwei Fassungen der Seite (e2e/pwa-update.spec.ts; Fassung 2 leitet e2e/versions.ts vor dem Test aus dist/ ab, der Test-Server liefert sie mit Cookie mw-version=2); Barrierefreiheit nach WCAG 2.2 AA (axe-core, e2e/a11y.spec.ts); einmalig: npx playwright install chromium
npm run gates    # alle Gates in der Reihenfolge der Pipeline
npm run gates:ci # alle Gates CI-nah in Docker (scripts/ci-local.sh): dieselben Schritte und Playwright-Projekte wie die Jobs der Pipeline, nacheinander in einem Container; Arbeitsstand samt Uncommittetem, 2 CPUs (CPUS=4 wie der Runner), Abhängigkeiten im Image je package-lock.json, Browser-Tests mit 2 Workern ohne Wiederholung, Dauer je Schritt (Warnung über 4 min e2e; rot, wenn test:deep über 150 s braucht, sonst bricht der Job static nach 5 min ab); bricht ab, wenn ein Projekt aus playwright.config.ts in keinem Browser-Job von deploy.yml steht; bei Rot test-results/ und playwright-report/ im Arbeitsbaum; grün schreibt den Tree-Hash nach .ci-local-ok. `npm run gates:ci -- e2e/pwa.spec.ts` oder `-- --project=game --shard=1/2` prüft schnell eine Auswahl (ohne .ci-local-ok)
# Git-Hook .githooks/pre-commit (aktiviert durch npm install) prüft vor jedem Commit Formatierung, Lint, Architektur, Tests
# Git-Hook .githooks/pre-push verlangt .ci-local-ok == Tree des gepushten Commits, sobald ein gepushter Commit mehr als Doku berührt (Ausnahmen wie `paths-ignore` in deploy.yml: README.md, CLAUDE.md, docs/)
```

Vor jedem Commit `npm run format`, `npm run lint`, `npm run arch`, `npm run check`, `npm test`, `npm run build`, `npm run verify` und `npm run test:e2e` ausführen.

## Regeln

- Schichten (geprüft durch `npm run arch`): `src/lib` ist generisch und importiert nichts aus `src/data`, `components`, `layouts`, `pages`, `scripts`. `src/data` kennt keine Oberfläche. Browser-Code in `src/scripts` nutzt aus `lib` nur `textures.ts` und `src/lib/games/`, nichts aus Node. `src/lib/games/` und `src/data/games/` laufen im Browser und nutzen aus `lib` nur `games/` und `textures.ts`.
- Design-Tokens aus `tokens.css` nutzen, keine neuen Farben ohne Grund. Gold ist die einzige Aktionsfarbe.
- Alle Inhalte bleiben im HTML; Interaktion ist Zusatz. Ohne JavaScript bleibt die Seite für Eltern lesbar, das Spiel zeigt einen `<noscript>`-Text.
- Keine Logos, Figuren oder Texturen aus Minecraft oder Hytale – nur eigene Voxel-Grafik.
- Keine externen Ressourcen ohne Klick des Nutzers (Schriften lokal). Geprüft durch `npm run verify:dist` (Logik in `scripts/dist.ts`).
- Animationen respektieren `prefers-reduced-motion`.
- Die Startseite bleibt schlank (geprüft durch `npm run verify:bundles`, Logik in `scripts/bundles.ts`): die Startseite lädt kein JavaScript (weder Datei noch eingebettetes Skript), Seiten außerhalb von `/spielen/` laden kein Spiel und kein Three.js und höchstens 32 KB JavaScript; die Spielseite lädt 3D nur nachträglich per `import()`.
- Grenzen mit Luft statt Tretmühle (Bundle-Gate `scripts/verify-bundles.ts`, App-Gate `PRECACHE_BUDGET`, Größen-Grenzen in `eslint.config.js`): Byte-Budgets liegen bei gemessen + gut 10 % (Three.js + 5 %, an seine Version gebunden, beim Update neu messen), Größen-Grenzen einzelner Dateien bei gemessen + gut 5 %. Angehoben wird erst, wenn weniger als 3 % Luft bleiben, dann wieder auf gemessen + 10 % (ESLint + 5 %), mit einem Satz Begründung in der Commit-Nachricht; beim Schrumpfen wird nicht von Hand gesenkt. Neben den Zahlen steht nur der letzte Messwert, kein Tagebuch. Die festen Regeln (Startseite ohne JavaScript, kein Spiel und kein Three.js außerhalb von `/spielen/`, Three.js nur per `import()`, Proben) bleiben unverändert.
- Welt-Pakete (`src/scripts/games/worlds/<welt>/`): Was nur eine Welt hinter einem Tor braucht (Gelände, Wohnorte, Regeln ihres Schlüssels, Zeichenteile und Wetter im Bild, Modelle ihrer Tiere), gehört in ihr Paket, nicht in den Kern. Einziger Einstieg `index.ts`, nur per `import()` geladen; nichts außerhalb importiert statisch daraus, Pakete importieren einander nicht (geprüft durch `npm run arch`). Ein Paket ohne eigene Welt (die Bahn) legt etwas in die gebauten Welten (`WorldPack.lay`) und rechnet nur aus deren Feldern. Die Fahrzeug-Engine `worlds/eis/mitwachsen-ride*.ts` importiert aus dem Paket nur `mitwachsen-flood.ts` (Regel `ride-engine-is-generic`), damit sie später mit allen Fahrzeugen in ein eigenes Paket (`worlds/fahrt/`) ziehen kann; was nur der Schlitten braucht, steht in `mitwachsen-sled*.ts`. Geladen wird es erst, wenn ihr Tor eine Rolle spielt (`needsPack`). Im Build heißt es `_astro/welt-<welt>.<hash>.js` und hat samt seinem 3D-Teil im Bundle-Gate eine eigene Grenze (`scripts/verify-bundles.ts`). Was die Welt nur in 3D zeigt, steckt in `worlds/<welt>/view-3d.ts` (`View3D`), geladen per `import()` aus `index.ts` (`view3d`) erst, wenn die 3D-Ansicht es will: `_astro/welt-<welt>-3d.<hash>.js`; die 3D-Ansicht (`mitwachsen-3d.ts`) enthält nichts, was nur eine Welt braucht (Regel „3D-Ansicht“ mit Probe). Fehlt ein Paket, läuft das Spiel ohne diese Welt, ohne etwas vom Spielstand zu verlieren; fehlt nur sein 3D-Teil, baut 3D schlicht.
- Der Service Worker gehört nur dem Spiel (`scope` `/spielen/`) und wird nur von der Spielseite angemeldet. `skipWaiting` und Neuladen nur auf Bitte des Spiels an sicheren Stellen (Gute Nacht im Bett, Rückkehr nach langer Pause, solange die Figur schläft; Entscheidungen in `src/scripts/games/pwa-update.ts`), nie mitten im Spiel. Alte Caches löscht erst die aktive neue Version, und nur, wenn keine andere Spielseite mehr offen ist. Die Liste der gespeicherten Dateien entsteht beim Build, nie von Hand, und bleibt im Budget (geprüft durch `npm run verify:pwa`). Gespeichert wird alles vorab, auch Three.js und jedes Welt-Paket samt 3D-Teil: Ohne Netz muss das Kind in jede offene Welt gehen können. Angemeldet wird mit `updateViaCache: 'none'`, nie `'all'`. Das Manifest legt die Drehung nicht fest.
- Keine Navigation per View Transitions (`ClientRouter`): Jede Seite lädt neu, das Spiel startet und endet sauber.
- TypeScript prüft jeden Index-Zugriff (`noUncheckedIndexedAccess`): fehlende Einträge behandeln; Auswahl aus Listen über `pick`/`cycle` (`src/lib/games/rng.ts`), Feld-Schlüssel über `fromKey` (`chunks.ts`). `!` nur, wo die Stelle selbst zeigt, dass der Eintrag existiert, und in Tests.
- Laufzeit der Unit-Tests (`vitest.config.ts`): Frist 60 s je Test und 120 s je Hook, lokal wie in der Pipeline, nur gegen Hänger; keine eigene Frist im Test. Tests über dem kalibrierten Budget (`scripts/test-budget.ts`, 4 s auf dem Bezugsrechner mit Abdeckung) meldet der Bericht nur als langsam. Welten kommen über `worldOf`/`bareOf` (`test-worlds.ts`), Tests einer Welt reichen nur ihr Paket herein (`worldOf(seed, [EIS_PACK])`), `expect` wird nicht in Schleifen je Takt oder Feld aufgerufen (Fehler sammeln, ein `expect`, Meldung nennt den Seed).
- Eigenschafts-Tests über viele Seeds laufen über `seedsFor(seedRange(…))` (`test-worlds.ts`): normal nur `SAMPLE_SEEDS` und `REGRESSION_SEEDS`, die vollen Bereiche unter `MITWACHSEN_DEEP=1` (`npm run test:deep`, Job `static` der Pipeline und `gates:ci`, hält also jeden Pull Request und Deploy auf); große Mengen mit `it.each(seedChunks(…))` in Abschnitte teilen. Scheitert ein Seed im tiefen Lauf, kommt er in `REGRESSION_SEEDS` (nur anhängen, nie streichen) und die Ursache wird behoben.
- Spielstände liegen nur im `localStorage` (Präfix `larmic.games.`, von larmic.de übernommen). Ändert sich das Format, gehört eine Migration in `mitwachsen-save.ts` mit Test.
- Pipeline (`.github/workflows/deploy.yml`) in parallelen Jobs: `static` (Format, Lint, Architektur, Typen, Unit-Tests über alle Seeds per `test:deep`), `coverage` (`npm test`), `build` (Build, verify, dist/ als Artefakt), `e2e-site` (Projekt `site`) und `e2e-game` (`game`, `3d`, `pwa-update`, `pwa-update-3d` in zwei Teilen per `--shard`) mit Blob-Berichten, `e2e-merge` (ein HTML-Bericht, wackelige Tests in die Zusammenfassung, kein Gate), `deploy` nur auf main nach allen Gates und nur, wenn kein neuerer Commit auf main mehr als Doku ändert. Jeder Job hat seine eigene Frist (etwa das 2,5-Fache der gemessenen Dauer). Neues Playwright-Projekt: in `e2e-site` oder `e2e-game` eintragen (`gates:ci` prüft das). Pull Requests brechen ältere Läufe ab, auf main bekommt jeder Push ein Urteil. Neue Actions auf den vollen Commit-SHA pinnen, Version als Kommentar.
- CI-naher Lauf (`npm run gates:ci`): Bevor dem Nutzer ein Feature als fertig gemeldet wird und vor jedem Push eines Stapels muss er auf dem finalen HEAD grün sein, auch nach Merges (der Pre-Push-Hook prüft `.ci-local-ok`). Lokale Läufe auf vielen Kernen sagen nichts über den 4-vCPU-Runner mit Software-WebGL. Ein roter oder wackliger Lauf wird nie wegerklärt („Flake“, „lokal grün“), sondern die Ursache behoben. Zeitgrenzen (`expect`, Test, Job) nur mit Trace und Begründung in der Commit-Nachricht anheben.
- Neue Browser-Tests nutzen `e2e/helpers.ts` (`openGame`/`reloadGame` warten auf den Zustand `settled`) und warten nie auf Uhrzeit (`waitForTimeout`) oder eine Zahl von Bildern, sondern auf einen Zustand (ESLint verbietet `waitForTimeout`, `frames`/`waitFrames` und `goto('/spielen/')` außerhalb der Helfer). Spiel-Tests laufen mit Test-Uhr (`openGame(page, { clock: true })`: `ticks(page, n)` spielt Takte, `render(page, n)` zeichnet Bilder, `play(page, ms)` beides wie die Seite; Haken `__MW_TEST` in `larmic-mitwachsen.ts`, Spec „Haken für die Browser-Tests“); nur „Spiel läuft live …“ bleibt ohne. Sie laufen im Projekt `game` in 2D; Tag `@3d` (`{ tag: '@3d' }`, zusätzlich im Projekt `3d` bzw. `pwa-update-3d` mit WebGL, dort mit `expectView`, damit er sicher in 3D zeichnet) nur, wenn der Test das Zeichnen in 3D prüft, die Bildschleife live laufen lässt, ein Welt-Paket fehlen, spät kommen oder die Welt wechseln lässt oder ein App-Update neu lädt; dazu je neuer Welt ein Eintrag in „Spiel: Welt … wird gezeichnet“. Keine eigene Frist im Test (`test.setTimeout`).
- Ändert sich eine Adresse, leitet die alte weiter (`redirects` in `astro.config.mjs`) und kommt in `LEGACY` in `scripts/verify-dist.ts`.
